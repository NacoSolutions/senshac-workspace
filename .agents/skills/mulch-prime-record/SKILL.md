# Mulch prime and record

Treat durable expertise as a small, reviewed artifact, not a transcript dump.

1. Before a non-obvious task, run the repository's configured `mulch prime`
   flow and read the returned guidance for the current repository and issue.
2. Apply only relevant guidance. Prefer existing conventions, gates, and
   ownership boundaries over inventing a parallel process.
3. After completing the task, run `mulch record` with the reusable lesson:
   context, decision, verification, and the scope where it is valid. Record
   commands or paths only when they are stable and portable.
4. Never record credentials, personal data, temporary tokens, copied logs, or
   an unverified workaround. If a lesson is repository-specific, label it as
   such; do not promote it to shared expertise.
5. Make the recorded result discoverable from the issue or PR when the local
   Mulch integration supports links, then verify that the record was accepted.

When Mulch is unavailable, continue with the repository's documented workflow
and leave a concise note for the next operator rather than fabricating output.
